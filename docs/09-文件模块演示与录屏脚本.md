## 二、界面演示顺序（与 5 个问题一一对应）

### 问题 1：大文件分片 + 重组 + 分片损坏重传（约 2 分钟）

1. 打开「① 大文件分片上传」页，选择 50MB 文件
2. **打开「模拟分片损坏」开关**
3. 点「开始上传」
4. 右侧日志会依次出现：
   - `开始上传：big-demo.bin，50.00 MB，MD5=...`
   - `待上传分片 10 个，并发 3`
   - `分片 0 第 1 次失败（code=4001）← 模拟损坏：分片 0 校验失败，请重传该分片`
   - `分片 0 自动重传（第 2 次）`
   - `合并完成并通过整体 MD5 校验`
5. 讲：**每片自带 MD5，落盘后立即比对；不一致就删掉该片并返回 4001，前端只重传这一片**

> 想再演示"整体校验失败"：直接改数据库里 `file_record.md5` 再 complete，会返回 4010。时间紧可不演。

### 问题 2：小文件批量上传（约 30 秒）

1. 切到「② 小文件批量上传」
2. 一次多选 5 个小文件，点「批量上传」
3. 进度条走完，表格里每个文件一行结果
4. 讲：**小文件不走分片（分片固定开销大于收益），一个 multipart 请求带多个文件，后端逐个落盘并各自返回结果**

### 问题 3：断点续传（上传 + 下载，约 1.5 分钟）

**上传**：
1. 传大文件到一半点「暂停」
2. 点「开始上传 / 继续」
3. 日志出现：`断点续传：服务端已有 N/10 片，只传缺失分片`

**下载**：
1. 切到「③ 下载」页，对一个文件点「下载」
2. 进度到 30% 左右点「暂停」
3. 再点「继续」→ 进度从 30% 接着走（日志显示 `从 xx MB 处继续`）

讲：**上传靠 `init` 返回已传分片序号；下载靠 HTTP `Range` 请求头 + 前端记录 offset**

### 问题 4：进度条（约 30 秒）

对着界面讲三种：
- 上传：`已完成分片数 / 总片数`（比字节级更稳，重传不倒退）
- 小文件批量：`axios onUploadProgress` 的 `loaded/total`
- 下载：`Range` 每段返回的字节累加 ÷ `fileSize`

强调：**下载进度必须靠后端返回 `Content-Length`**，否则没法算百分比。

### 问题 5：高并发下载（约 1 分钟）

1. 同一个文件点「4 线程并行」
2. 日志显示 `4 线程并行下载完成，耗时 xx ms`
3. 讲三层：
   - 后端 `StreamingResponseBody` 8KB 缓冲流式写出，**不把文件读进内存**
   - 前端把文件切 4 段，同时发 4 个 `Range` 请求，最后拼 Blob
   - 生产可让 Nginx `sendfile` 直接发静态文件 / `X-Accel-Redirect`，应用只做鉴权

## 三、程序讲解部分（约 3 分钟，打开代码讲）

按这个顺序讲 4 个文件，每个 40 秒左右：

| 顺序 | 文件 | 讲什么 |
|---|---|---|
| 1 | `modules/file/controller/FileController.java` | 5 个接口：`init` / `upload/chunk` / `complete` / `upload/batch` / `download`；下载为什么用 `StreamingResponseBody` |
| 2 | `modules/file/service/FileService.java` | `init`（秒传 + 返回已传分片）、`uploadChunk`（分片 MD5 校验，4001）、`complete`（按 index 顺序合并 + 整体 MD5） |
| 3 | `database/file_module.sql` | 两张表，`uk_md5` 用于秒传，`uk_file_chunk` 防并发重复分片 |
| 4 | `frontend/src/views/file/FileDemo.vue` | 切片 `file.slice()`、SparkMD5 算分片 MD5、并发池、暂停/继续、并行下载 |

### 讲到这几个细节会很加分

- **合并顺序**：必须按 `chunkIndex` 升序，不能按文件名排序（`10` 会排在 `2` 前面）
- **分片命名**：`%06d.part` 六位补零，人工排查也直观
- **并发控制**：分片并发 3，避免把浏览器连接和服务器 IO 打满
- **秒传**：同 MD5 已存在直接返回下载地址，日志里有 `命中秒传`
- **幂等**：`file_chunk` 的唯一索引保证重复上传同一片不会产生脏数据

## 五、常见问题（录制时可能遇到）

| 现象 | 原因/处理 |
|---|---|
| 上传立刻失败，code=4001 | 正常（开着「模拟分片损坏」开关），日志会自动重传成功 |
| 点在「继续」后进度不动 | 需要点「开始上传 / 继续」按钮重新 init，会跳过已传分片 |
| 下载进度不动 | 确认后端在跑；`Range` 请求返回 206 才算正常 |
| 502 / 接口全red | 后端没启动，或 8080 被占用 |
| 秒传没有触发 | 传同一个文件第二次才会命中（MD5 相同） |
| 大文件上传很慢 | 本地磁盘 + 5MB 分片，50MB 约 1~2 秒/片，属正常 |
