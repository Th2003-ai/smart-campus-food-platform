## 二、账号登录：三道前端护栏 + 一条清理规则

1. **本地图形验证码（第一道）**
   进页面即生成 4 位验证码，画在 canvas 上：字符带随机旋转/字号/颜色，另有干扰曲线和噪点。
   验证码原文只存在于组件内部变量，**不写 DOM、不写 localStorage**，所以简单脚本读不到。
   验证不通过就不发登录请求 —— 这是「防爬虫」的实际落点：脚本必须先有渲染并识别图片的能力，
   才轮得到去猜密码。

2. **失败节流（第二道）**
   连续失败 5 次 → 登录按钮锁定 30 秒并显示倒计时；登录成功清零。
   状态放 `sessionStorage`，用户清掉或直接打接口都能绕过，**它是体验层，不是安全边界**。

3. **真正的防线在后端（第三道）**
   `AuthController#login` 上的 `@RateLimit(limit = 10, seconds = 60, by = IP)`；
   账号或密码错误统一提示「账号或密码错误」（不区分账号是否存在，避免账号枚举）；
   密码 BCrypt 存储、登录失败不落明文日志。前端节流只是让正常用户先看到提示。

4. **失败即清理**
   登录失败：清空密码框与验证码、立刻换一张验证码；
   页面不再展示任何演示口令（原来那行「演示账号密码见 database/README.md」已删掉，演示账号只留在
   `database/README.md` 与 `DevDataInitializer` 里）；
   输入框 `autocomplete` 设为 `username` / `new-password`，减少浏览器把口令存进自动填充库；
   页面不提供「记住密码」，口令只随 `POST /auth/login` 请求体发送一次。

> 补充：生产部署必须走 HTTPS，否则口令在链路上仍是明文——这一点前端做不了，记在部署清单里。

## 三、短信登录：本地验证码 + 演示账号

### 3.1 为什么验证码也放本地

接入真实短信网关需要企业资质、签名报备和费用，课程环境不具备；且按约定「验证相关能力先不上服务器」。
所以短信验证码由浏览器生成、浏览器保管、浏览器比对，页面上明确标注「本地演示：未接入短信网关」，
并把**本次验证码直接显示出来**（附带「一键填入」），保证没有手机也能把流程走完。

规则按真实短信登录的口径写死，将来换成后端只需要替换数据来源：

| 规则 | 取值 | 位置 |
| --- | --- | --- |
| 验证码位数 | 6 位数字（允许前导 0） | `SMS_CODE_LENGTH` |
| 有效期 | 5 分钟 | `SMS_TTL_SECONDS` |
| 重发间隔 | 60 秒（按钮倒计时） | `SMS_RESEND_SECONDS` |
| 最多尝试 | 5 次，用尽后必须重新获取 | `SMS_MAX_ATTEMPTS` |
| 手机号校验 | `1[3-9]` 开头 11 位，自动去空格/短横线 | `isValidPhone` |

### 3.2 登录链路

短信验证码只证明「手机号可控」，拿不到 JWT；后端目前也没有 `/auth/sms/login`。
因此本地校验通过后，前端用**本机配置的演示账号**调用真实的 `POST /auth/login` 换取登录态，
并在提示里说明「短信登录成功（本地演示，手机号 1xx****xxxx）」。改手机号会作废当前验证码，
避免「发给 A 的码用来登 B」。

### 3.3 配置本地演示账号（可选）

`frontend/.env.local`（已被 `.gitignore` 忽略）：

```dotenv
# 是否展示本地演示验证码：留空 = 仅 dev 显示
VITE_LOGIN_SMS_DEMO=true

# 验证码通过后用来换 JWT 的演示账号（不配置则只演示界面，不真的登录）
VITE_LOGIN_SMS_DEMO_ACCOUNT=20210001
VITE_LOGIN_SMS_DEMO_PASSWORD=你的本地演示口令
```

未配置时点「登录」会提示去 `.env.local` 补配置，面板上也有一行黄色提示。

> 顺带一个环境坑：后端 `campus.cors.allowed-origins` 是白名单（默认 `localhost:5173`、`127.0.0.1:5173`、
> `*.campus.local:8088`、`localhost:8088~8091`）。把 dev server 换到白名单外端口（例如 5199）时，
> 登录会返回 `403 Invalid CORS request`，这不是登录逻辑的问题。

## 四、扫码登录：本地演示，不碰服务器

### 4.1 为什么不上服务器

扫码登录天然需要「服务端下发一次性票据 → 手机端确认 → 浏览器轮询/长连接拿结果」，也就是要新增：

- `POST /auth/qr/create`（生成票据，Redis 存 TTL）
- `GET /auth/qr/poll` 或 WebSocket 推送扫码状态
- App 端的扫码识别与确认接口、登录态绑定

这套东西目前没有做的必要（没有 App、也没有对应的服务），硬接会引入一个「演示用假接口」，
反而给后续联调添乱。所以本次做成**纯前端可视演示**：

### 4.2 现在的行为

| 状态 | 界面 | 说明 |
| --- | --- | --- |
| `waiting` | 显示二维码 + 剩余秒数 + 票号 | 二维码内容是一段本地票据文本 `CAMPUS-QR-<票号>-<时间戳>`，用手机扫出来能看到，但不指向任何后端地址 |
| `scanned` | 蒙层提示「已扫码，请在手机上确认」 | 由「模拟手机扫码」按钮触发 |
| `confirmed` | 「已确认，正在登录…」 | 由「模拟手机确认」按钮触发，父组件用**本地演示账号**调用真实的 `/auth/login` |
| `expired` | 蒙层「二维码已失效 / 点击刷新」 | 120 秒倒计时归零自动进入，点击可重新生成 |

「模拟手机扫码 / 模拟手机确认」两个按钮默认**只在 `npm run dev` 时出现**（`import.meta.env.DEV`），
可以用 `VITE_LOGIN_QR_DEMO=true|false` 强制开关；演示构建想用，就显式设成 `true`。

### 4.3 配置本地演示账号（可选）

在 `frontend/.env.local`（已被 `.gitignore` 忽略）里写：

```dotenv
# 是否显示「模拟手机」按钮：留空 = 仅 dev 显示
VITE_LOGIN_QR_DEMO=true

# 扫码确认后用来登录的本地演示账号（不配置则只演示界面，不真的登录）
VITE_LOGIN_QR_DEMO_ACCOUNT=20210001
VITE_LOGIN_QR_DEMO_PASSWORD=你的本地演示口令
```

口令**不要写进 `.env.development`、`.env.example` 或任何 `.vue/.ts` 文件**：Vite 会把 `VITE_` 变量
打进前端产物，等于把口令公开。`.env.local` 是本机私有文件，不进仓库。

未配置时，点「模拟手机确认」会提示去 `.env.local` 补配置，面板上也会显示一行黄色提示。

## 五、二维码为什么是自己实现的

- 环境装不了第三方包（离线 / 受限），`qrcode` 之类的依赖加不进来；
- 扫码登录只需要画一个 25~53 模块的二维码，用不着完整实现（版本 1~9、纠错 L 足够 226 字节）。

`utils/qrcode.ts` 覆盖：Byte 模式编码 → 终止符/填充 → RS 纠错分块交错 → 定位/定时/校正图形 →
格式信息 BCH → 之字形填点 → 8 种掩码按标准罚分择优。

**正确性验证**：拿公开参考实现（qrcode-generator 1.4.4）对同一段内容生成矩阵，逐模块比对。
因为我的掩码是按罚分自选的，脚本对 8 个掩码各生成一次，只要有一个与参考实现完全一致即视为通过：

```text
PASS  CAMPUS-LOCAL-QR-ABC123       size=25 mask=4
PASS  CAMPUS-LOCAL…(31B)           size=25 mask=2
PASS  A                            size=21 mask=0
PASS  demodemodemodemodemodemo     size=25 mask=4
PASS  xxxxxxxxxxxx…(100B)          size=37 mask=0
PASS  yyyyyyyyyyyy…(200B)          size=53 mask=3
```

即版本 1 / 2 / 5 / 9 上的数据编码、RS 纠错、交错、填点、格式信息与参考实现逐位一致。
（自测脚本与参考源码放在 `temp/`，该目录已在 `.gitignore` 中，不入库。）

## 七、后续真正上线时要做的事

1. 后端下发图形验证码：`GET /auth/captcha` 返回 `captchaId + base64 图片`，答案存 Redis（TTL 2 分钟，一次性），
   登录请求带 `captchaId + captchaCode` 校验，校验失败也计入限流。
2. 短信登录：`POST /auth/sms/send`（按手机号 + IP 限流，Redis 存验证码 TTL 5 分钟，60 秒内不可重发）+
   `POST /auth/sms/login`（校验后一次性消费，未注册手机号走自动注册），前端把本地校验替换成这两个接口。
3. 扫码登录：`POST /auth/qr/ticket`（Redis 存 `qr:<ticket>`，状态 `WAITING/SCANNED/CONFIRMED/EXPIRED`）+
   `GET /auth/qr/status?ticket=` 轮询（或复用现有 WebSocket 通道推送），App 端确认后把 ticket 绑定到 userId，
   浏览器拿到一次性登录票据换 JWT。
4. 前端把本地节流换成后端返回的「剩余锁定时间」，避免前后端口径不一致。
